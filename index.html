Local startup alternative

Requires Git, Python 3.11+ and a running Docker engine with Compose. These commands use Linux/macOS paths. On Windows use .venv/Scripts/python instead of .venv/bin/python.

git clone https://github.com/texasbredmj/agent-operations-control-center.git
cd agent-operations-control-center
git checkout 2147f79a6c2bc5ca89e0134f137ed5ee5e411f17
python -m venv .venv
.venv/bin/python -m pip install -r requirements.lock .
.venv/bin/python scripts/init_local.py
docker compose up -d --build --wait
.venv/bin/python scripts/demo.py

Expected summary: verified_demo=true, scenarios=8, paid_model_calls=0. Open the local application ↗. Read generated role tokens from the ignored .env in your editor; never share them. Reloading the application clears login. Initialization refuses to replace an existing credential file.

Rerunning the seed demo appends tasks; it does not reset the database. Stop with docker compose down to preserve the volume.

0 of 5 steps marked complete

  1. Create a task. Inspect its receipt.

    Sign in as operator. Choose + New task → Inventory reservation, use quantity 2, and submit. Find the task under Completed tasks and open Evidence.

    Expected SUCCEEDED, verified=true, observed_quantity=2.

  2. Make an approval decision.

    As operator, create a Reservation requiring approval. Record its ID. Sign out, sign in as approver, find it in Pending approvals and approve with a reason. Try rejection on a separate task.

    Expected PENDING_APPROVAL until the approver acts. Approval produces verified completion; rejection produces REJECTED without an effect. Operator and viewer cannot approve.

  3. Recover a temporary failure.

    As operator, create Temporary failure → eligible retry. After FAILED, inspect the task, choose Retry, supply a reason and confirm.

    Expected SUCCEEDED on attempt 2 with a verified receipt.

  4. Investigate the mismatch.

    Create Receipt mismatch → investigation with quantity 2. Compare the tool claim in Tools with independent verification in Evidence.

    Expected FAILED and verified=false despite the tool's completion claim. Quantity differs; retry is ineligible.

  5. Follow the execution trail.

    Inspect Workflow, Tools and Traces for a task. Then open Execution traces, Reliability metrics, Resource usage and Cost reports.

    Expected Matching task trace IDs and inspectable history. Model cost and token counters are zero; shared worker resource counters are identified separately.

04 / ENGINEERING CONTRIBUTION

Decisions worth discussing.

The system combines task controls, server-enforced permissions and independent receipt checks. Personal design, implementation and testing attribution, AI assistance, and lessons learned need owner review before the resume is published.

Reproducibility vs. realism. A deterministic database effect makes verification and recovery repeatable; its guarantees stop at that fixture boundary.

Simple setup vs. production identity. Separate generated role tokens demonstrate backend authorization; production requires credential expiry, rotation and an identity provider.
