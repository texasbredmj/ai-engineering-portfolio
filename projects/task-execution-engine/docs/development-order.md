# Development order

Follow the master prompt's phases. Each project must produce verified executable software before
the next project begins. GitHub publication and cloud deployment require separate authorization.

1. **Project 01 — Task Execution Engine:** P0 validation, authorization, states, persistence,
   controlled execution, audit, and verification first; then the deterministic maintenance demo
   with formatting/lint checks and explicitly authorized corrections followed by re-verification.
2. **Project 02 — AI Tool Coordination Gateway:** typed tool registry, discovery, schema validation,
   backend permissions, invocation, timeouts, concurrency/rate limits, idempotency, approval gates,
   and three realistic adapters, with deterministic service tests.
3. **Project 03 — Autonomous Workflow Orchestrator:** durable dependencies, checkpoints, interruption
   and resumption without silently duplicated side effects.
4. **Project 04 — Agent Evaluation Harness:** deterministic benchmarks and regression evidence.
5. **Project 05 — Agent Failure & Recovery Lab:** repeatable fault injection and recovery evidence.
6. **Project 06 — Multi-Provider Model Gateway:** capability-aware routing and authorized fallbacks.
7. **Project 07 — AI-Native CI/CD Quality Gates:** deterministic application quality gates.
8. **Project 08 — Agent Operations Control Center:** authorized backend operations and dashboard.

The portfolio index should reflect verified project evidence as projects are delivered. It must
not advertise planned projects as completed implementations. Local CI checks and a configured
workflow do not establish that remote GitHub Actions has run.
